# 벌레 퇴치녀 — 1구간(1~10스테이지)

`index.html`을 브라우저로 열면 바로 실행된다. 빌드 도구 없음.

조작: WASD / 방향키 이동, 공격은 자동, P / Esc 일시정지, 버프 카드는 클릭 또는 1·2·3 키.

## 파일

```
index.html, style.css       화면 틀과 UI(타이틀·카드·버튼은 전부 CSS)
js/data.js                  ★ 수치·스테이지 구성·구간·무기 데이터 (밸런스는 여기만 고친다)
js/assets.js                json/이미지 로더
js/sprite.js                애니메이션(Animator), 스프라이트·fx 그리기, 피격 번쩍임
js/world.js                 맵 크기 계산, 카메라, 보이는 부분만 바닥 그리기, 테두리, 몹 출현 위치
js/weapons.js               무기 동작(WEAPON_KINDS)
js/entities.js              플레이어, 몹, 몹 AI(MOB_AI)
js/game.js                  스테이지·웨이브 진행, 하트, HUD, 버프 선택
js/json_bundle.js           자동 생성(아래 참고). 직접 고치지 않는다
tools/update_json_bundle.ps1  json_bundle.js 를 다시 만드는 스크립트
assets/                     stage1_assets.zip + zone2_assets.zip 원본
                            (zone2의 README.md·preview.png는 1구간 것과 이름이 겹쳐 README_zone2.md·preview_zone2.png로 넣음)
```

## json 읽기와 file:// 문제

프레임 크기·피벗·fps는 코드에 없고 각 에셋 json에서 읽는다.
그런데 index.html을 더블클릭(file://)으로 열면 브라우저가 보안상 json 파일 읽기(fetch)를 막는다.
그래서 두 가지 경로를 둔다.

- **http로 열 때**(VS Code Live Server, GitHub Pages): json 파일을 직접 읽는다.
- **file://로 열 때**: `js/json_bundle.js`(모든 json을 그대로 복사해 둔 파일)를 읽는다.
  json을 고치거나 바꿔 넣었으면 `tools/update_json_bundle.ps1`을 우클릭 → "PowerShell에서 실행"한다.
- 번들 갱신을 잊어도 시트 이미지 크기가 json과 다르면 이미지 기준으로 프레임 크기를 맞추고 콘솔에 경고를 남긴다.

## 자주 할 일

- **밸런스 조정**: `js/data.js`의 `mobs`, `weapons`, `zones[].stages`, `player`, `heartDrop`.
- **맵 크기·몹 수 늘리는 정도**: `js/data.js`의 `world`(맵 크기 공식, 특정 스테이지 직접 지정은 `overrides`)와 `scaling`(몹 수·강화 개체 비율·동시 최대 수).
- **플레이어 그림 교체**: `assets/sprites/z01/player/` 안의 `player.json`, `player_sheet.png`를 같은 이름으로 바꿔 넣는다(위의 번들 갱신 포함).
  그림의 몸이 프레임 가운데에 있지 않으면 json의 `pivot`을 `[x, y]` 숫자로 적어 발 위치를 직접 지정할 수 있다(예: `"pivot": [49, 76]`).
- **무기 추가**: `data.js`의 `weapons` 항목에 `base`/`upgrade`를 채우고 `enabled: true`.
  동작이 기존과 같으면 `kind`만 맞추고, 새 동작이면 `js/weapons.js`의 `WEAPON_KINDS`에 하나 추가한다.
  동작 하나가 가질 수 있는 함수: `update`(매 프레임), `drawUnder`(캐릭터 아래 그리기), `drawOver`(캐릭터 위 그리기), `onPlayerHurt`(플레이어가 맞기 직전, true면 피해를 막음).
- **2구간 추가**: 그림을 `assets/sprites/z02/`, `assets/tiles/z02/`에 넣고, `data.js`의 `zones` 배열에 `z02` 항목(타일·몹 그림 경로·스테이지 11~20)을 추가한다.
  새 몹은 `mobs`에 능력치를 넣고, 새 행동이 필요하면 `js/entities.js`의 `MOB_AI`에 함수 하나를 추가한다.

## 처음 정한 값(조정 필요)

수치는 사용자가 아직 정하지 않아 임시로 정했다. 실제로 플레이해 보고 고쳐야 한다.

- 하트 5개, 맞으면 1초 무적. 몹 공격은 전부 하트 1개.
- 8~10스테이지 `_alt` 개체는 체력 ×1.6, 속도 ×1.15.
- 보스: 체력 180, 웅크렸다가 돌진, 9초마다 개미 3마리 소환. 보스가 죽으면 소환된 개미도 함께 쓰러진다.
- 하트 드랍 확률 = 1.5 / 스테이지 몹 수(맵 크기에 맞춰 늘린 뒤의 수). 보스가 소환한 개미는 하트를 떨어뜨리지 않는다.
  체력이 가득하면 하트를 줍지 않고, 스테이지를 클리어하면 바닥에 남은 하트는 자동으로 회복된다.
- BRIEF 무기 13종 전부 구현. 버프 카드에서 빼고 싶은 무기는 `enabled: false`.

## 구현 방식 기록

- 애니메이션: `requestAnimationFrame` 한 루프에서 캐릭터마다 경과 시간을 누적하고, 프레임 = `floor(시간 × json fps)`로 계산한다.
  캐릭터마다 시간을 따로 들고 있어서 몹 수가 늘어도 타이머가 늘지 않는다. 그림은 스프라이트 시트 한 장에서 잘라 그린다.
- 피격 흰색 번쩍임: 프레임을 임시 캔버스에 그린 뒤 `source-atop`으로 흰색을 덮어 몸 모양에만 칠한다.
- 사망: die 애니메이션이 끝난 뒤 0.6초 동안 투명도를 줄인다.

## 맵(월드)과 카메라

- 화면(캔버스)은 1280×720 그대로이고, 맵은 스테이지마다 커진다. 1스테이지 = 1280×720, 100스테이지 ≈ 가로·세로 4.5배.
  보스 스테이지(10, 20…)는 직전 스테이지와 같은 크기.
- 몹 수 = data의 웨이브 수 × (맵 넓이 비)^0.8. 보스는 늘지 않는다. 몹이 많아지면 나오는 간격도 줄어든다.
- 강화 개체(_alt): `alt: true` 스테이지는 전부, 그 밖에는 (스테이지−1)×1.2% 확률(최대 60%).
- 몹은 화면 바로 바깥(맵 안쪽)에서 나온다. 맵이 화면만 할 때는 맵 가장자리에서 서서히 나타난다.
  플레이어와 1100px 넘게 멀어진 몹은 화면 근처로 다시 옮겨진다. 남은 몹이 5마리 이하이거나 보스면 화면 가장자리에 방향 화살표가 뜬다.
- 바닥 타일은 칸 좌표로 정해지는 난수로 골라서, 화면에 보이는 칸만 매 프레임 그린다.

## 2구간(11~20스테이지, 동굴)

- 몹: 점프 거미(돌진), 바위 타란툴라(근접·탱커), 독침 거미(원거리, 투사체 `fx_web_shot`). 18~20스테이지는 `_alt` 색 변형.
  1구간 같은 역할 몹보다 체력 약 1.7배·속도 약 1.1배, 스테이지별 몹 수 약 1.3배(그 위에 맵 크기 배율이 곱해짐).
- 보스 거대 거미(20스테이지, 체력 320): 거리를 두고 맴돌며
  - 거미줄 함정(`fx_web_trap`): 6초마다 플레이어 발밑과 주변에 3개. 0.5초 뒤부터 밟으면 1.1초 속박(이동 불가). 9초 뒤 사라짐
  - 거미줄 줄기(`fx_web_beam`): 4초마다. 0.7초 조준(예고선, 마지막 40%는 빨갛게 고정) 뒤 발사. 맞으면 하트 1 + 2.5초 동안 이동 속도 ×0.45
  - 11초마다 점프 거미 2마리 소환
  - 모기장이 줄기를 막으면 둔화도 걸리지 않는다. 함정 속박은 피해가 아니라서 막지 못한다
- 수치는 전부 `data.js`의 `mobs.spider_*`, `mobs.boss_spider`, `zones[1]`.
